SECTION 2  ABSTRACT
Mental health disorders among university students remain critically underaddressed due to prevailing social stigma, insufficient institutional resources, and the absence of accessible, privacy-respecting digital intervention tools. Studies indicate that over 35% of undergraduate students globally experience clinically significant psychological distress, yet fewer than 20% seek formal counseling. This gap necessitates a technology-driven, stigma-free support ecosystem.
Clarity is a full-stack MERN (MongoDB, Express.js, React.js, Node.js) web platform engineered to bridge this gap. The system employs a document-oriented NoSQL schema (MongoDB) to manage heterogeneous data structures arising from anonymous peer forums, AI conversation logs, and longitudinal mood telemetry. A JWT-secured authentication layer with bcrypt hashing ensures user identity protection, while role-based access control (RBAC) enforces data segregation between students, counselors, and administrators.
The AI module integrates NLP-based regex pattern matching and keyword corpus analysis for real-time crisis detection, triggering automated SOS escalations to designated counselors. The mood tracking subsystem persists daily affective state logs, enabling time-series visualization via Chart.js-powered dashboards. An anti-ragging portal provides anonymized grievance submission with admin-level case management. Clarity does not serve as a clinical diagnostic tool; rather, it functions as a supplementary mental wellness infrastructure, ultimately reducing the average time-to-support for at-risk students from weeks to minutes.
	
SECTION 3  INTRODUCTION
3.1  Overview — Mental Wellness in Modern Academia
The intersection of academic performance pressure, social isolation, financial stress, and identity formation renders university students disproportionately vulnerable to psychological distress. The World Health Organization (WHO) identifies depression and anxiety as leading causes of disability among individuals aged 18–24. Traditional institutional counseling services are constrained by appointment bottlenecks, geographic inaccessibility, and the persistent stigma that deters self-referral. Digital mental health platforms have demonstrated clinical efficacy in adjunctive roles, offering scalability, 24/7 availability, and measurable outcome tracking unavailable in conventional models.
3.2  Purpose
Clarity provides a stigma-free, technology-driven environment for psychological self-monitoring, peer support, and graduated crisis escalation. The platform is designed to:
•	Lower the activation barrier for students seeking mental health resources.
•	Enable longitudinal mood data collection without clinical overhead.
•	Provide automated, real-time crisis triage through AI-driven detection.
•	Facilitate anonymous peer interaction to reduce isolation-driven distress.
•	Equip institutional administrators with aggregated wellness analytics for policy decisions.
3.3  Scope — Core Modules
Module 1 — AI Chatbot: A conversational interface powered by NLP keyword detection and predefined intervention protocols. The chatbot handles passive wellness queries, guided breathing prompts, and escalates to live SOS alerts upon detecting high-risk linguistic patterns.
Module 2 — Anonymous Peer Forums: Threaded discussion boards where students interact under system-generated pseudonyms. Posts undergo server-side identity masking, and moderators retain the ability to flag or remove content without exposing author identity.
Module 3 — Anti-Ragging Portal: A secure grievance submission interface enabling victims to file detailed complaints with optional evidence attachments. Complaints are routed to the admin role via encrypted document storage, maintaining strict confidentiality.
Module 4 — Mood Tracking Dashboard: A daily mood self-assessment interface backed by a time-series log schema in MongoDB. Visualization renders 7-day, 30-day, and 90-day rolling charts, enabling personal trend analysis and counselor-accessible progress reports.
Module 5 — SOS Trigger System: A one-click emergency escalation button integrated into every authenticated view. Upon activation, it dispatches a real-time WebSocket notification to the on-call counselor dashboard, logs the event with geolocation metadata, and presents the student with crisis helpline information.
3.4  Limitations
IMPORTANT DISCLAIMER: Clarity is an academic support tool and does not constitute a clinical diagnostic system. It is not designed to replace licensed psychiatric or psychological services. The AI chatbot does not perform DSM-5 or ICD-11 evaluations. Mood data collected within the platform is not clinically validated for diagnostic inference. Users exhibiting symptoms of acute psychiatric conditions must be directed to registered mental health professionals.

•	FR-AUTH-02: Passwords shall be hashed using bcrypt with a minimum salt round of 12 before storage.

•	FR-MOOD-02: The system shall persist mood logs in the MOOD_LOGS collection with a compound unique index on (userId, date) to prevent duplicate entries.
•	FR-MOOD-03: The dashboard shall render time-series line charts with 7, 30, and 90-day granularity windows using client-side Chart.js integration.
•	FR-MOOD-04: Counselors assigned to a student shall have read-only access to that student's aggregated mood history.
•	FR-MOOD-05: A rolling 3-day average mood score below 4.0 shall automatically flag the student's account for counselor review.
4.3  Crisis Support & AI Intervention
•	FR-CRISIS-01: The AI chatbot shall maintain a curated keyword corpus of 200+ terms spanning suicidal ideation, self-harm, acute distress, and ragging-related abuse language.
•	FR-CRISIS-02: All chat input shall be passed through the crisis detection regex pipeline before the AI generates a response.
•	FR-CRISIS-03: Positive crisis detection shall trigger: (a) an immediate WebSocket push notification to the assigned counselor, (b) an SOS banner in the student UI, and (c) logging of the trigger event with timestamp and anonymized conversation excerpt.
•	FR-CRISIS-04: The SOS manual trigger button shall be accessible on all authenticated views without requiring additional navigation steps.
4.4  Anonymous Peer Forums
•	FR-FORUM-01: Student identities shall be replaced with deterministic pseudonyms (e.g., 'MapleFox#4821') generated via HMAC-SHA256 hash of userId + forumSalt, ensuring consistent pseudonym per user per forum context.
•	FR-FORUM-02: Moderators (Counselor role) shall be able to flag, hide, or delete posts; flagged posts shall be queued in the admin review panel.
•	FR-FORUM-03: The system shall support threaded replies up to 3 levels of nesting depth to maintain readability.
•	FR-FORUM-04: Forum posts shall not store direct userId references in the posts document; only a hashed identifier shall be persisted.
4.5  Admin Panel
•	FR-ADMIN-01: The admin dashboard shall display aggregated, non-PII (Personally Identifiable Information) analytics: daily active users, average mood scores by department, crisis trigger frequency, and forum activity metrics.
•	FR-ADMIN-02: Anti-ragging complaints shall be accessible exclusively to Admin-role users; each complaint shall have a workflow state: Received, Under Review, Resolved.
•	FR-ADMIN-03: Admins shall be able to assign/unassign counselors to students from the management panel.
•	FR-ADMIN-04: All admin actions shall be captured in an immutable audit log with actor ID, timestamp, and action description.
	
SECTION 5  DATA MODELLING & DATABASE DESIGN
5.1  Rationale for MongoDB (NoSQL)
Clarity's data landscape is inherently heterogeneous and schema-volatile. Forum posts vary structurally based on media attachments, thread depth, and moderation metadata. AI conversation logs grow dynamically with variable message counts per session. Mood journal entries incorporate optional free-text fields. These characteristics make a fixed relational schema inefficient — schema migrations would be frequent, and JOIN-heavy queries for user-forum interactions would impose significant performance overhead at scale.
MongoDB's document model resolves these constraints through: (a) flexible BSON documents that accommodate evolving schemas without downtime migrations; (b) embedded sub-documents for denormalized co-located data such as mood tag metadata; (c) native support for time-series-adjacent patterns via compound indexes on (userId, date); and (d) horizontal sharding capability to distribute the forums collection across shards as concurrent user volume scales. The platform uses Mongoose ODM for schema enforcement at the application layer, preserving data integrity without enforcing rigid database-level constraints.
5.2  Entity Relationships
Users → MoodLogs (1:M): One user document can reference many MoodLog documents via userId foreign key. The compound unique index on {userId, date} enforces the one-log-per-user-per-day business rule at the database level.
Users → Posts (1:M via hash): Users author many forum posts; however, the direct userId is not stored in the Posts collection. Only the HMAC pseudonym hash is persisted, severing the direct referential link to enforce anonymity even at the database query level.
Users → Complaints (1:M): A single student may submit multiple anti-ragging complaints. Each complaint document embeds a status field for workflow state tracking and references an optional array of encrypted file attachment IDs.
Users → ChatSessions (1:M): Each user can initiate many AI chat sessions. Sessions embed a messages array of sub-documents (role, content, timestamp, crisisFlag), enabling full conversation history retrieval in a single document fetch.

5.4  Indexing Strategy
•	MOOD_LOGS: Compound unique index { userId: 1, date: 1 } — enforces one-log-per-day constraint and optimizes dashboard range queries.
•	USERS: Unique index { email: 1 } — fast authentication lookup; sparse index on { assignedCounselor: 1 } for counselor workload queries.
•	POSTS: Index { forumId: 1, createdAt: -1 } — supports paginated thread retrieval sorted by recency.
•	CHAT_SESSIONS: Index { userId: 1, updatedAt: -1 } — efficient retrieval of a user's most recent sessions.

7.1  User Model — Mongoose Schema (models/User.js)

// models/User.js
const mongoose = require('mongoose');
const bcrypt   = require('bcryptjs');
 
const UserSchema = new mongoose.Schema(
  {
    name: {
      type:     String,
      required: [true, 'Name is required'],
      trim:     true,
      maxlength: [100, 'Name cannot exceed 100 characters']
    },
    email: {
      type:      String,
      required:  [true, 'Email is required'],
      unique:    true,
      lowercase: true,
      match:     [/^\S+@\S+\.\S+$/, 'Invalid email format']
    },
    passwordHash: {
      type:     String,
      required: true,
      select:   false   // Excluded from all default queries
    },
    role: {
      type:    String,
      enum:    ['student', 'counselor', 'admin'],
      default: 'student'
    },
    department:        { type: String },
    assignedCounselor: { type: mongoose.Schema.Types.ObjectId, ref: 'User' },
    pseudonymSalt:     { type: String, select: false },
    isFlagged:         { type: Boolean, default: false },
    lastActive:        { type: Date }
  },
  { timestamps: true }   // Adds createdAt & updatedAt automatically
);
 
// Pre-save hook: hash password only when modified
UserSchema.pre('save', async function (next) {
  if (!this.isModified('passwordHash')) return next();
  this.passwordHash = await bcrypt.hash(this.passwordHash, 12);
  next();
});
 
// Instance method: constant-time password comparison
UserSchema.methods.comparePassword = async function (candidate) {
  return bcrypt.compare(candidate, this.passwordHash);
};
 
// Index for fast counselor workload lookups
UserSchema.index({ assignedCounselor: 1 }, { sparse: true });
 
module.exports = mongoose.model('User', UserSchema);

7.2  Mood Submission API Endpoint (routes/mood.js)

// routes/mood.js  — POST /api/mood
const express    = require('express');
const { body, validationResult } = require('express-validator');
const MoodLog    = require('../models/MoodLog');
const { protect } = require('../middleware/auth'); // JWT verification
 
const router = express.Router();
 
// Validation middleware
const moodValidators = [
  body('moodScore')
    .isInt({ min: 1, max: 10 })
    .withMessage('moodScore must be an integer between 1 and 10'),
  body('emotionTag')
    .isIn(['happy','sad','anxious','angry','neutral','overwhelmed'])
    .withMessage('Invalid emotion tag'),
  body('journalEntry')
    .optional()
    .isLength({ max: 500 })
    .withMessage('Journal entry cannot exceed 500 characters')
];
 
router.post('/', protect, moodValidators, async (req, res) => {
  const errors = validationResult(req);
  if (!errors.isEmpty())
    return res.status(422).json({ errors: errors.array() });
 
  try {
    // Normalize to UTC midnight for compound-index deduplication
    const today = new Date();
    today.setUTCHours(0, 0, 0, 0);
 
    const log = await MoodLog.findOneAndUpdate(
      { userId: req.user.id, date: today },
      { ...req.body, userId: req.user.id, date: today },
      { upsert: true, new: true, runValidators: true }
    );
 
    // Check rolling 3-day average for counselor flag trigger
    const recent = await MoodLog.find({
      userId: req.user.id,
      date:   { $gte: new Date(Date.now() - 3 * 86400000) }
    }).select('moodScore');
 
    const avg = recent.reduce((s, l) => s + l.moodScore, 0) / recent.length;
    if (avg < 4.0) {
      await User.findByIdAndUpdate(req.user.id, { isFlagged: true });
      // TODO: Dispatch WebSocket notification to assigned counselor
    }
 
    return res.status(201).json({ success: true, data: log });
  } catch (err) {
    console.error('[MoodLog Error]', err.message);

});

7.3  AI Crisis Keyword Detection Logic (utils/crisisDetector.js)

// utils/crisisDetector.js
// NLP-lite crisis detection via curated keyword corpus + regex patterns
 
const CRISIS_KEYWORDS = [
  // Suicidal ideation
  'want to die', 'end my life', 'kill myself', 'no reason to live',
  'better off dead', 'suicidal', 'commit suicide', 'take my own life',
  // Self-harm
  'hurt myself', 'cut myself', 'self harm', 'self-harm', 'burning myself',
  // Acute distress
  'can\'t take it anymore', 'everything is hopeless', 'no way out',
  'nobody cares', 'completely alone', 'mental breakdown',
  // Ragging / abuse
  'being ragged', 'seniors threatening', 'forced to do', 'being bullied',
  'physical abuse', 'sexual harassment',
  // Substance crisis
  'overdose', 'took too many pills'
];
 
// High-severity patterns warrant immediate SOS (not just flagging)
const HIGH_SEVERITY_PATTERNS = [
  /\b(i (will|am going to) (kill|hang|shoot) (my)?self)\b/i,
  /\b(tonight (i|it) (ends|is over))\b/i,
  /\b(took (an |a |\d+ )?overdose)\b/i,
  /\b(goodbye (world|everyone|forever))\b/i
];
 
/**
 * Analyse a single text string for crisis indicators.
 * @param {string} text - Raw user input from chat or forum post.
 * @returns {{ triggered: boolean, severity: 'none'|'low'|'high', matches: string[] }}
 */
function detectCrisis(text) {
  if (!text || typeof text !== 'string')
    return { triggered: false, severity: 'none', matches: [] };
 
  const normalised = text.toLowerCase().trim();
  const matches    = [];
 
  // Check high-severity regex first (short-circuit for immediate SOS)
  for (const pattern of HIGH_SEVERITY_PATTERNS) {
    if (pattern.test(normalised)) {
      return { triggered: true, severity: 'high', matches: [pattern.source] };
    }
  }
 
  // Check keyword corpus
  for (const keyword of CRISIS_KEYWORDS) {
    if (normalised.includes(keyword)) {
      matches.push(keyword);
    }
  }
 
  if (matches.length === 0)
    return { triggered: false, severity: 'none', matches: [] };
 
  return {
    triggered: true,
    severity:  matches.length >= 2 ? 'high' : 'low',
    matches
  };
}
 
module.exports = { detectCrisis };

SECTION 8  CONCLUSION
8.1  Project Summary
Clarity successfully demonstrates the viability of a MERN-stack, NoSQL-backed mental health support infrastructure within an academic environment. The platform achieves its primary design objectives: zero-barrier entry to psychological self-monitoring through JWT-secured authentication, real-time crisis triage through NLP-driven keyword detection, and community-level support via cryptographically anonymized peer forums. The anti-ragging portal introduces a critical institutional compliance layer previously absent from most campus digital systems.
The MongoDB document model proved decisively advantageous for this domain. The schema-flexible nature of BSON documents accommodated evolving requirements across the mood logging, AI conversation, and forum subsystems without requiring disruptive migrations. Mongoose's application-layer schema enforcement maintained data integrity while preserving the agility required during iterative development cycles.
8.2  Scalability of the NoSQL Design
The current single-instance MongoDB deployment is architected with horizontal scalability in mind. The MOOD_LOGS collection's compound index on (userId, date) supports efficient shard key selection, enabling range-based sharding as student volume grows. The CHAT_SESSIONS collection's embedded message array model reduces inter-document lookups, keeping read latency sub-millisecond even under concurrent load. The POSTS collection's use of hashed identifiers rather than ObjectId references permits independent horizontal scaling of the forum database tier without compromising the anonymity architecture.
MongoDB Atlas's auto-scaling cluster configuration, combined with the stateless Express.js API tier behind a load balancer, positions Clarity to scale from a single-institution deployment to a multi-university SaaS model without architectural refactoring.
8.3  Future Enhancements

6. Queries interact with MongoDB (CRUD, aggregation)
7. Response flows back through the chain to React
8. TanStack Query caches and updates UI

5. DATA MODELLING & DATABASE DESIGN
--------------------------------------------------------------------------------

A. DATABASE APPROACH & ARCHITECTURE

Database System:
The Clarity platform uses MongoDB Atlas as its primary database with 16 collections, 
following a NoSQL document-oriented data model. This choice provides:
• Flexible schema for evolving feature requirements
• Horizontal scalability for growing user base
• Built-in cloud hosting and automatic backups
• Native support for complex nested data structures
• Transaction support for multi-document operations (MongoDB 4.0+)

Database Configuration:
• Cloud Provider: MongoDB Atlas (AWS-backed)
• Collections: 16 dedicated collections for different data domains
• Indexing: Strategic indexing for performance optimization
• TTL Indexes: Auto-deletion of temporary data (e.g., 24-hour anonymous posts)
• Validation: Zod schemas for strict input validation
• Replication: Multi-region for high availability

B. ENTITY RELATIONSHIP MODEL

Core Entities & Relationships:

User (Central Entity)
├─→ One User HAS MANY Mood Entries (1:M)
├─→ One User HAS MANY Goals (1:M)
├─→ One User HAS MANY Journal Entries (1:M)
├─→ One User HAS MANY Community Posts (1:M)
├─→ One User HAS MANY Reactions (1:M)
├─→ One User HAS ONE Reaction Streak (1:1)
├─→ One User HAS MANY Mentorships (as Mentee or Mentor) (1:M)
├─→ One User HAS MANY Chat Messages (1:M)
├─→ One User HAS MANY Crisis Reports (1:M)
├─→ One User HAS ONE Profile Settings (1:1)
└─→ One User HAS MANY Assessments Completed (1:M)

Therapist (Extended User Profile)
├─→ One Therapist HAS MANY Appointments (1:M)
├─→ One Therapist HAS MANY Patients (M:M)
└─→ One Therapist HAS ONE Supervisor (M:1)

Mentorship
├─→ One Mentorship CONNECTS Mentor + Mentee (2 User references)
├─→ One Mentorship HAS MANY Tasks (1:M)
└─→ One Mentorship HAS ONE Status (Active/Completed)

Community Post
├─→ One Post BELONGS TO One Community (M:1)
├─→ One Post AUTHORED BY One User (M:1)
├─→ One Post HAS MANY Comments (1:M)
├─→ One Post HAS MANY Reactions (1:M)
└─→ One Post HAS ONE TTL Index (Auto-delete if anonymous after 24h)

Assessment
├─→ One Assessment HAS MANY Questions (1:M)
├─→ One Assessment HAS MANY User Responses (1:M)
└─→ One Assessment MAY LINK TO Many Diagnoses (M:M)

D. KEY DATABASE OPERATIONS

CRUD Utilities (from db-utilities.ts):
• findById(collection, id) - Retrieve single document by ObjectId
• insertOne(collection, doc) - Create new document with auto-ID
• insertMany(collection, docs[]) - Batch insert multiple documents
• updateById(collection, id, updates) - Update with auto-timestamp
• deleteById(collection, id) - Remove document
• paginate(collection, filter, page, size) - Offset-based pagination
• aggregate(collection, pipeline) - MongoDB aggregation pipelines
• increment(collection, id, field, amount) - Atomic counter updates
• addToArray(collection, id, field, value) - Push to array field

Performance Indexes:
• User queries: userId (unique), email (unique)

• Mentorship queries: mentorId/menteeId + status for filtering

CODE SNIPPET 1: EXPRESS.JS BACKEND SERVER SETUP & AUTH ROUTES
================================================================================
Location: server/index.ts
Description: Core Express server setup with authentication endpoints

```typescript
import express, { Request, Response } from "express";
import { connectDB, getDB } from "./db-mongo-updated";
import { insertOne, findById, updateById } from "./db-utilities";
import bcrypt from "bcrypt";
import jwt from "jsonwebtoken";

const app = express();
const PORT = process.env.PORT || 5000;
const JWT_SECRET = process.env.JWT_SECRET || "dev_secret";

app.use(express.json());
app.use((req, res, next) => {
  res.header("Access-Control-Allow-Origin", "*");
  res.header("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE");
  res.header("Access-Control-Allow-Headers", "Content-Type, Authorization");
  next();
});

// Health Check Endpoint
app.get("/health", (req, res) => {
  res.status(200).json({ status: "operational", timestamp: new Date() });
});

// User Registration
app.post("/api/auth/register", async (req: Request, res: Response) => {
  try {
    const { username, email, password, firstName, lastName } = req.body;
    
    if (!username || !email || !password) {
      res.status(400).json({ error: "Username, email, and password required" });
      return;
    }

    const db = getDB();
    
    // Check for existing user
    const existingUser = await db
      .collection("users")
      .findOne({ $or: [{ email }, { username }] });
    
    if (existingUser) {
      res.status(409).json({ error: "User already exists" });
      return;
    }

    // Hash password and create user
    const hashedPassword = await bcrypt.hash(password, 10);
    const userId = `USR-${Date.now()}-${Math.random().toString(36).substr(2, 9)}`;
    
    const newUser = {
      userId,
      username,
      email,
      password: hashedPassword,
      firstName: firstName || "",
      lastName: lastName || "",
      role: "user",
      createdAt: new Date(),
      updatedAt: new Date(),
      isActive: true
    };

    await insertOne("users", newUser);
    
    // Generate JWT token
    const token = jwt.sign({ userId, email, username }, JWT_SECRET, {
      expiresIn: "7d"
    });

    res.status(201).json({
      ok: true,
      token,
      user: { userId, username, email, firstName, lastName }
    });
  } catch (error) {
    const message = error instanceof Error ? error.message : "Registration failed";
    res.status(500).json({ error: message });
  }
});

// User Login
app.post("/api/auth/login", async (req: Request, res: Response) => {
  try {
    const { username, password } = req.body;
    
    if (!username || !password) {
      res.status(400).json({ error: "Username and password required" });
      return;
    }

    const db = getDB();
    const user = await db.collection("users").findOne({
      $or: [{ username }, { email: username }]
    });

    if (!user) {
      res.status(401).json({ error: "Invalid credentials" });
      return;
    }

    // Verify password
    const isPasswordValid = await bcrypt.compare(password, user.password);
    
    if (!isPasswordValid) {
      res.status(401).json({ error: "Invalid credentials" });
      return;
    }

    // Generate JWT token
    const token = jwt.sign(
      { userId: user.userId, email: user.email, username: user.username },
      JWT_SECRET,
      { expiresIn: "7d" }
    );

    res.status(200).json({
      ok: true,
      token,
      user: {
        userId: user.userId,
        username: user.username,
        email: user.email,
        firstName: user.firstName,
        lastName: user.lastName
      }
    });
  } catch (error) {
    const message = error instanceof Error ? error.message : "Login failed";
    res.status(500).json({ error: message });
  }
});

// Middleware to verify JWT
const verifyToken = (req: Request, res: Response, next: Function) => {
  const authHeader = req.headers.authorization;
  const token = authHeader?.split(" ")[1];

  if (!token) {
    res.status(401).json({ error: "No token provided" });
    return;
  }

  try {
    const decoded = jwt.verify(token, JWT_SECRET) as any;
    (req as any).userId = decoded.userId;
    next();
  } catch (error) {
    res.status(401).json({ error: "Invalid token" });
  }
};

// Start Server
app.listen(PORT, async () => {
  await connectDB();
  console.log(`✓ Clarity server running on port ${PORT}`);
});
```

CODE SNIPPET 2: MOOD TRACKING & ANALYTICS - REACT COMPONENT
================================================================================
Location: client/src/components/mood-tracker.tsx
Description: React component for mood logging with data visualization

```typescript
import { useState, useEffect } from "react";
import { useQuery, useMutation } from "@tanstack/react-query";
import { LineChart, Line, XAxis, YAxis, CartesianGrid, Tooltip, Legend } from "recharts";
import { Button } from "@/components/ui/button";
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
import { Slider } from "@/components/ui/slider";

interface MoodEntry {
  date: string;
  moodLv: number;
  notes?: string;
}

export function MoodTracker() {
  const [currentMood, setCurrentMood] = useState(5);
  const [notes, setNotes] = useState("");
  const [selectedRange, setSelectedRange] = useState("7d");

  // Fetch mood history
  const { data: moodHistory, refetch } = useQuery({
    queryKey: ["/api/mood-history", selectedRange],
    queryFn: async () => {
      const response = await fetch(`/api/mood-history?range=${selectedRange}`, {
        headers: { Authorization: `Bearer ${localStorage.getItem("authToken")}` }
      });
      return response.json();
    }
  });

  // Submit mood entry
  const { mutate: submitMood, isPending } = useMutation({
    mutationFn: async () => {
      const response = await fetch("/api/mood-entries", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          Authorization: `Bearer ${localStorage.getItem("authToken")}`
        },
        body: JSON.stringify({
          moodLv: currentMood,
          notes,
          date: new Date().toISOString()
        })
      });
      return response.json();
    },
    onSuccess: () => {
      setNotes("");
      setCurrentMood(5);
      refetch();
    }
  });

  // Calculate statistics
  const calculateStats = (data: MoodEntry[]) => {
    if (!data.length) return { avg: 0, highest: 0, lowest: 0, trend: "stable" };
    
    const moods = data.map((e) => e.moodLv);
    const avg = Math.round(moods.reduce((a, b) => a + b) / moods.length * 10) / 10;
    const highest = Math.max(...moods);
    const lowest = Math.min(...moods);
    
    // Simple trend detection
    const first = moods[0];
    const last = moods[moods.length - 1];
    const trend = last > first + 1 ? "improving" : last < first - 1 ? "declining" : "stable";
    
    return { avg, highest, lowest, trend };
  };

  const stats = calculateStats(moodHistory?.data || []);

  // Emoji based on mood level
  const getMoodEmoji = (level: number) => {
    if (level <= 2) return "😢";
    if (level <= 4) return "😟";
    if (level <= 6) return "😊";
    if (level <= 8) return "😄";
    return "🤩";
  };

  return (
    <div className="space-y-6">
      {/* Mood Logging Card */}
      <Card>
        <CardHeader>
          <CardTitle>How are you feeling today?</CardTitle>
        </CardHeader>
        <CardContent className="space-y-4">
          {/* Mood Display */}
          <div className="flex justify-center items-center gap-4">
            <span className="text-6xl">{getMoodEmoji(currentMood)}</span>
            <span className="text-4xl font-bold text-teal-600">{currentMood}/10</span>
          </div>

          {/* Mood Slider */}
          <Slider
            value={[currentMood]}
            onValueChange={(val) => setCurrentMood(val[0])}
            max={10}
            min={1}
            step={1}
            className="w-full"
          />

          {/* Notes Input */}
          <textarea
            placeholder="What's on your mind? (optional)"
            value={notes}
            onChange={(e) => setNotes(e.target.value)}
            className="w-full p-3 border rounded-lg focus:outline-none focus:ring-2 focus:ring-teal-500"
            maxLength={500}
          />

          {/* Submit Button */}
          <Button
            onClick={() => submitMood()}
            disabled={isPending}
            className="w-full bg-teal-600 hover:bg-teal-700"
          >
            {isPending ? "Logging..." : "Log Mood"}
          </Button>
        </CardContent>
      </Card>

      {/* Statistics Cards */}
      <div className="grid grid-cols-2 md:grid-cols-4 gap-4">
        <Card>
          <CardContent className="pt-6">
            <div className="text-center">
              <div className="text-2xl font-bold text-teal-600">{stats.avg}</div>
              <div className="text-sm text-gray-600">Average</div>

        </Card>
        <Card>
          <CardContent className="pt-6">
            <div className="text-center">
              <div className="text-2xl font-bold text-green-600">{stats.highest}</div>

        <Card>

              <div className="text-2xl font-bold text-red-600">{stats.lowest}</div>

        <Card>
          <CardContent className="pt-6">
            <div className="text-center">
              <div className="text-lg font-bold capitalize">{stats.trend}</div>
              <div className="text-sm text-gray-600">Trend</div>
            </div>
          </CardContent>

      <Card>
        <CardHeader>

              {["7d", "30d", "90d"].map((range) => (
                <Button
                  key={range}
                  variant={selectedRange === range ? "default" : "outline"}

                  onClick={() => setSelectedRange(range)}

                  {range}
                </Button>
              ))}
            </div>
```

```typescript
import { useState, useRef, useEffect } from "react";
import { useMutation } from "@tanstack/react-query";
import { Button } from "@/components/ui/button";
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
import { AI_PERSONALITIES } from "@/shared/ai-personalities";

interface Message {
  role: "user" | "assistant";
  content: string;
  timestamp: Date;
}

interface Personality {
  id: string;
  name: string;
  emoji: string;
  specialty: string;
  welcomeMessage: string;
  systemPrompt: string;
}

export function AIChat() {
  const [selectedPersonality, setSelectedPersonality] = useState<string | null>(null);
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [isTyping, setIsTyping] = useState(false);
  const messagesEndRef = useRef<HTMLDivElement>(null);

  const personality = selectedPersonality
    ? AI_PERSONALITIES[selectedPersonality as keyof typeof AI_PERSONALITIES]
    : null;

  // Auto-scroll to latest message
  useEffect(() => {
    messagesEndRef.current?.scrollIntoView({ behavior: "smooth" });
  }, [messages]);

  // AI Chat Mutation
  const { mutate: sendMessage, isPending } = useMutation({
    mutationFn: async (userMessage: string) => {
      // Detect crisis keywords
      const crisisKeywords = ["suicide", "kill", "harm", "die", "death"];
      const isCrisis = crisisKeywords.some((keyword) =>
        userMessage.toLowerCase().includes(keyword)
      );

      if (isCrisis) {
        setIsTyping(false);
        return {
          content: "I'm concerned about what you're sharing. Please reach out to a crisis service immediately: National Suicide Prevention Lifeline: 988 | Crisis Text Line: Text HOME to 741741",
          isCrisis: true
        };
      }

      const response = await fetch("/api/ai-chat", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          Authorization: `Bearer ${localStorage.getItem("authToken")}`
        },
        body: JSON.stringify({
          personality: selectedPersonality,
          messages: messages.map((m) => ({ role: m.role, content: m.content })),
          userMessage,
          systemPrompt: personality?.systemPrompt
        })
      });

      return response.json();
    },
    onSuccess: (data) => {
      setMessages((prev) => [
        ...prev,
        {
          role: "assistant",
          content: data.content,
          timestamp: new Date()
        }
      ]);
      setIsTyping(false);
    }
  });

  const handleSendMessage = () => {
    if (!input.trim() || !selectedPersonality || isPending) return;

    // Add user message
    const userMessage = input;
    setMessages((prev) => [
      ...prev,
      { role: "user", content: userMessage, timestamp: new Date() }
    ]);
    setInput("");
    setIsTyping(true);

    // Call AI
    sendMessage(userMessage);
  };

  const handlePersonalitySelect = (personalityId: string) => {
    setSelectedPersonality(personalityId);
    setMessages([
      {
        role: "assistant",
        content: AI_PERSONALITIES[personalityId as keyof typeof AI_PERSONALITIES].welcomeMessage,
        timestamp: new Date()
      }
    ]);
  };

  // Personality Selector
  if (!selectedPersonality) {
    return (
      <div className="space-y-6">
        <h1 className="text-3xl font-bold">Meet Your Wellness Buddies</h1>
        <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-5 gap-4">
          {Object.entries(AI_PERSONALITIES).map(([id, pers]) => (
            <Card
              key={id}
              className="cursor-pointer hover:shadow-lg transition-shadow"
              onClick={() => handlePersonalitySelect(id)}
            >
              <CardContent className="pt-6 text-center">
                <div className="text-5xl mb-3">{pers.emoji}</div>
                <h3 className="text-xl font-bold mb-2">{pers.name}</h3>
                <p className="text-sm text-gray-600 mb-3">{pers.specialty}</p>
                <Button className="w-full">Start Chat</Button>
              </CardContent>
            </Card>
          ))}
        </div>
      </div>
    );
  }

  // Chat Interface
  return (
    <div className="flex flex-col h-screen">
      {/* Header */}
      <Card className="rounded-none">
        <CardContent className="pt-6 flex items-center justify-between">
          <div className="flex items-center gap-3">
            <span className="text-4xl">{personality?.emoji}</span>
            <div>
              <h2 className="text-xl font-bold">{personality?.name}</h2>
              <p className="text-sm text-gray-600">{personality?.specialty}</p>
            </div>
          </div>
          <Button
            variant="outline"
            onClick={() => {
              setSelectedPersonality(null);
              setMessages([]);
              setInput("");
            }}
          >
            Change Buddy
          </Button>
        </CardContent>
      </Card>

      {/* Messages */}
      <div className="flex-1 overflow-y-auto p-4 space-y-4">
        {messages.map((msg, idx) => (
          <div
            key={idx}
            className={`flex ${msg.role === "user" ? "justify-end" : "justify-start"}`}
          >
            <div
              className={`max-w-xs lg:max-w-md px-4 py-2 rounded-lg ${
                msg.role === "user"
                  ? "bg-teal-600 text-white rounded-br-none"
                  : "bg-gray-200 text-black rounded-bl-none"
              }`}
            >
              <p>{msg.content}</p>
              <p className="text-xs opacity-70 mt-1">
                {msg.timestamp.toLocaleTimeString()}
              </p>
            </div>
          </div>
        ))}
        {isTyping && (
          <div className="flex justify-start">
            <div className="bg-gray-200 px-4 py-2 rounded-lg">
              <div className="flex gap-1">
                <div className="w-2 h-2 bg-gray-600 rounded-full animate-bounce" />
                <div className="w-2 h-2 bg-gray-600 rounded-full animate-bounce delay-100" />
                <div className="w-2 h-2 bg-gray-600 rounded-full animate-bounce delay-200" />
              </div>
            </div>
          </div>
        )}
        <div ref={messagesEndRef} />
      </div>

      {/* Input */}
      <div className="border-t p-4 flex gap-2">
        <input
          type="text"
          placeholder="Type your message..."
          value={input}
          onChange={(e) => setInput(e.target.value)}
          onKeyPress={(e) => e.key === "Enter" && handleSendMessage()}
          className="flex-1 px-4 py-2 border rounded-lg focus:outline-none focus:ring-2 focus:ring-teal-500"
          disabled={isPending}
        />
        <Button
          onClick={handleSendMessage}
          disabled={isPending || !input.trim()}
          className="bg-teal-600 hover:bg-teal-700"
        >
          {isPending ? "..." : "Send"}
        </Button>
      </div>
    </div>
  );
}
```

```typescript
import { Db, ObjectId, Collection } from "mongodb";

let db: Db | null = null;

export function setDB(database: Db) {
  db = database;
}

export function getDB(): Db {
  if (!db) throw new Error("Database not initialized");
  return db;
}

// Generic Find by ID
export async function findById<T>(
  collectionName: string,
  id: string | ObjectId
): Promise<T | null> {
  const collection = getDB().collection(collectionName);
  return collection.findOne({
    $or: [{ _id: new ObjectId(id) }, { id }]
  }) as Promise<T | null>;
}

// Generic Insert One
export async function insertOne<T>(
  collectionName: string,
  document: Partial<T> & { _id?: ObjectId }
): Promise<string> {
  const collection = getDB().collection(collectionName);
  const result = await collection.insertOne({
    ...document,
    createdAt: new Date(),
    updatedAt: new Date()
  } as any);
  return result.insertedId.toString();
}

// Generic Update By ID
export async function updateById<T>(
  collectionName: string,
  id: string | ObjectId,
  updates: Partial<T>
): Promise<boolean> {
  const collection = getDB().collection(collectionName);
  const result = await collection.updateOne(
    { $or: [{ _id: new ObjectId(id) }, { id }] },
    {
      $set: {
        ...updates,
        updatedAt: new Date()
      }
    }
  );
  return result.modifiedCount > 0;
}

// Generic Delete By ID
export async function deleteById(
  collectionName: string,
  id: string | ObjectId
): Promise<boolean> {
  const collection = getDB().collection(collectionName);
  const result = await collection.deleteOne({
    $or: [{ _id: new ObjectId(id) }, { id }]
  });
  return result.deletedCount > 0;
}

// Generic Find Multiple
export async function find<T>(
  collectionName: string,
  filter: any = {}
): Promise<T[]> {
  const collection = getDB().collection(collectionName);
  return collection.find(filter).toArray() as Promise<T[]>;
}

// Count Documents
export async function count(
  collectionName: string,
  filter: any = {}
): Promise<number> {
  const collection = getDB().collection(collectionName);
  return collection.countDocuments(filter);
}

// Pagination
export async function paginate<T>(
  collectionName: string,
  filter: any = {},
  page: number = 1,
  pageSize: number = 20
): Promise<{ data: T[]; total: number; pages: number }> {
  const collection = getDB().collection(collectionName);
  const skip = (page - 1) * pageSize;
  
  const data = (await collection
    .find(filter)
    .skip(skip)
    .limit(pageSize)
    .toArray()) as T[];
  
  const total = await collection.countDocuments(filter);
  const pages = Math.ceil(total / pageSize);
  
  return { data, total, pages };
}

// Atomic Increment
export async function increment(
  collectionName: string,
  id: string | ObjectId,
  field: string,
  amount: number = 1
): Promise<boolean> {
  const collection = getDB().collection(collectionName);
  const result = await collection.updateOne(
    { $or: [{ _id: new ObjectId(id) }, { id }] },
    { $inc: { [field]: amount }, $set: { updatedAt: new Date() } }
  );
  return result.modifiedCount > 0;
}

// Add to Array
export async function addToArray(
  collectionName: string,
  id: string | ObjectId,
  field: string,
  value: any
): Promise<boolean> {
  const collection = getDB().collection(collectionName);
  const result = await collection.updateOne(
    { $or: [{ _id: new ObjectId(id) }, { id }] },
    { $push: { [field]: value }, $set: { updatedAt: new Date() } }
  );
  return result.modifiedCount > 0;
}

// Aggregation Pipeline
export async function aggregate<T>(
  collectionName: string,
  pipeline: any[]
): Promise<T[]> {
  const collection = getDB().collection(collectionName);
  return collection.aggregate(pipeline).toArray() as Promise<T[]>;
}
```
